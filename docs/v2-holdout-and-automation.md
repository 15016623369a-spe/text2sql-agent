# V2 补注留出验证、自动化与回归复盘

## 200 道留出题

评测使用预先冻结的 200 道 BIRD Mini-Dev 题，与 50 道开发题的 ID 无交集。11 个数据库仍来自同一个 BIRD 快照，验证范围是同库新题。人工补注先冻结并发起评测，自动规则及测试定稿后才解封对照结果。各组均使用项目原有的 `deepseek-flash`、温度 0、原有的 BM25 Top-4 与外键补表、每题一次模型请求、SQLite 5 秒期限。逐题核对了相同的表列、系统提示、题目与证据，变化只在字段补注段。所有 600 次留出评测请求均有模型返回和 token 用量，执行准确率通过 [BIRD 官方 EX 函数](https://github.com/bird-bench/mini_dev/blob/1c49a375e76c471e218564da3f4617513d33e371/evaluation/evaluation_ex.py) 复核。

- **V2 无补注**为 **74/200（37%）**。输入 **165,552** token，总计 **186,346** token。
- **V2 人工补注**为 **94/200（47%，+10pp）**。25 题由错变对、5 题由对变错。逐题配对 McNemar 双侧精确检验 `p = 0.000325`。输入 **219,676** token（相对无补注 **+32.69%**），总计 **240,370** token。
- **V2 自动补注**为 **76/200（38%，+1pp）**。14 题由错变对、12 题由对变错，配对 `p = 0.845`。输入 **191,266** token（相对无补注 **+15.53%**，相对人工补注 **−12.93%**），总计 **211,806** token。开发集为 **23/50（46%）**，输入 **48,853** token，相对 V1 输入 **−4.65%**、EX **+4pp**。

人工补注在同库新题上保留了收益，50 道开发题上的 **+26pp** 回落为 **+10pp**。自动版的 **+1pp** 尚无明确的增益证据，比人工版低 9pp。两版保留独立选项，自动版暂作为实验运行。按题配对的检验反映此题集的差异，跨库迁移尚待单独验证。首次调用因 Python 的证书配置失败，未收到模型回复。更换为项目原有环境并通过真实请求预检后重跑，这里的数字来自成功批次。当前评测命令遇到请求或 schema 准备失败会返回失败状态并保留日志。

## 自动补注管线

`app/auto_column_notes.py` 负责相关性排序和存储画像，`evaluation/bird_column_notes.py` 把 BIRD 的字段字典接入这条管线。代码按现有 SQL schema 识别真实列名，结合题目和证据匹配列名及字段含义，降低常见词的权重。候选只来自检索选中的表，不借用表名的相关性。每题最多 6 条、850 字符。

对命中列所在的表最多只读抽取 256 行，并把文本探测长度限制为 96 字符。可识别数字文本、前导零、月份 `YYYYMM`、比较符开头的数值、空串、全空格和采样全 NULL。对于官方已列出的简单枚举，仅在采样匹配到这些文档标签时校对大小写。缓存保留生成的画像，模型提示只包含字段文档、画像描述和经核对的文档枚举标签。业务语义仍取自文档，例如 0 是否表示缺失。首批抽样只能验证样本中出现的形式，稀有编码和跨表业务含义仍是局限。

## 三道由对变错的题

用开发集归档的无补注和完整补注提示，再加入一组只删弱相关补注的提示。每题每个条件独立调用 5 次，共 45 次，以固定种子混排。保留原有表、题目与证据。筛选后的条件是对人工提示的删减实验，另有完整自动管线的评测。

- **118，帖子最后编辑者，5/5 → 4/5 → 0/5。** `posts.LastEditorDisplayName` 在命中的那条帖子上是 NULL，`LastEditorUserId` 关联到的 `users.DisplayName` 有值。筛选保留了语义最相像的冗余字段，却删掉了 `LastEditorUserId` 的补注。只剩 120 个额外输入 token 的提示比完整补注的 247 个更差，结果支持字段提示偏置，完整补注下也有波动。
- **250，意大利赛道最快圈，0/5 → 0/5 → 5/5。** 无补注的历史正确结果未复现，两种原提示都对文本圈速取 `MIN`。两条赛道的文本最小值与按毫秒比较的结果都不同。筛选后只保留 `results.fastestLapTime` 的补注，5 次均从 `results` 得到同样的正确执行结果。该 SQL 使用了另一张表，且两条赛道恰好与参考答案一致。原选表缺少 `circuits`、`races`，因此这组结果不能证明筛选修复了选表或数值比较。
- **353，男性 God / Eternal 英雄的平均超能力数，5/5 → 0/5 → 0/5。** 17 位符合条件的英雄中，3 位没有超能力关联。无补注从英雄全集做 `LEFT JOIN`，补注组从 `hero_power` 出发，漏掉这 3 位。缩短后仍重复出现同一种错误。结果支持补注改变了查询起点，说明相关性筛选还需要保留实体范围和关联方向。原选表也缺少 `gender` 和 `race`。

三题在自动版开发集的单次实测中均未修复。相关性筛选可以削减无关字段，但在高相似字段冲突、数值排序和零计数等情况下仍需要结构证据。

## 同一批 50 道开发题的 token 总账

- **V1 → V2 选表。** 输入 **51,236 → 42,175**，省 **9,061（−17.68%）**。EX **42% → 38%**。
- **V2 → 人工补注。** 输入 **42,175 → 55,838**，增加 **13,663（+32.40%）**，约每题 **+273**。EX **38% → 64%（+26pp）**，净多答对 13 道，每净增一道正确题增加 **1,051 输入 token**。
- **V1 → V2 加人工补注。** 两段合计增加 **4,602 输入 token（+8.98%）**，约每题 **+92**。EX **42% → 64%（+22pp）**，净多答对 11 道，每净增一道正确题约 **418 输入 token**。输入与输出总计 **58,000 → 62,215（+4,215，+7.27%）**。这里比较的是 token 量，实付金额还受缓存命中和价格影响。

## 复现与回归门槛

在项目根目录和原有 `chat-data-agent` 环境中运行。每次变更提示后都运行这套测试。目前原 7 项和新增 3 项共 **10/10**。新增用例覆盖编码检测、带引号的字段和枚举、相关性筛选与长度限制。

```bash
python -m unittest discover -s tests -v
python -m evaluation.run_v2 --split eval --workers 8
python -m evaluation.run_v2 --split eval --column-notes --workers 8
python -m evaluation.run_v2 --split eval --auto-column-notes --workers 8
```

`--split dev` 仍为默认。留出结果可复查，但后续调整用开发集迭代，新的泛化结论使用新的未见题目。
