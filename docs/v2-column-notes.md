# V2 字段说明与值编码补注

在项目根目录激活 `chat-data-agent` 环境后运行：

```bash
python -m evaluation.run_v2 --column-notes
```

流程先用原来的 BM25 和外键补表选表，再在完整表定义后追加单独的 `Column metadata` 段。每条补注挂在实际的 `表名.列名` 下，分别标记字段含义和存储值规则。候选只来自已选表，按题目及官方提示的词项相关度排序，优先放入经过核实的编码补注。每题最多 8 条、合计最多 1,300 字符。

基础说明来自 BIRD 随库发布的字段 CSV。补充规则按数据库、表、列维护，来源是官方字段说明和本地只读聚合核实。经核实的编码优先于 CSV 的旧描述。例如学校代码可能带前导零，`district.A4` 是文本形式的人口，`district.A11` 是平均工资，`height_cm` 和 `weight_kg` 的 0 表示缺失。模型请求包含这些元数据、题目和官方提示。参考 SQL 与查询结果留在本地评分环节。

## 2026-11-10 开发集对照

- 固定 V2 的 50 道开发题、数据库版本、`deepseek-flash`、温度 0、单次模型调用、SQLite 5 秒期限和 EX 评分。逐题比对确认，入选表、列、外键补表、系统提示、题目与证据完全一致，补注是提示里的唯一变化。
- 执行准确率从 **19/50（38%）** 到 **32/50（64%）**，增加 **26 个百分点**。16 道由错变对、3 道由对变错，后者为 118、250 和 353。官方 EX 函数复核了 32/50。[BIRD 官方评分函数](https://github.com/bird-bench/mini_dev/blob/1c49a375e76c471e218564da3f4617513d33e371/evaluation/evaluation_ex.py)
- 在诊断时划出的 16 道字段含义或值编码题中，有 10 道由错变对。第 9 题使用整数转换匹配带前导零的学校代码，第 203 题对人口文本做数值排序，第 368 题跳过表示缺失的 0，第 146 题改用了链接记录自己的创建时间。
- 输入 token 从 **42,175** 增至 **55,838**（**+32.4%**）。表列召回率保持一致。P95 延迟从 3.07 秒变为 2.78 秒，属于这两次运行的观测值。
- 部分补注根据这批开发题的排查结果选定。这是单轮开发集实验，泛化效果仍需留出集验证。

原 V2 的启动命令为 `python -m evaluation.run_v2`。补注版的逐题记录位于 `evaluation/results/v2-notes-20261110T041728478130Z/`，其中 `column_notes` 保存了每道题实际发送的补注。
